# 个人记录功能设计文档（含“我的”页优化）

> 本文档描述“我的”页优化与个人记录功能的完整设计，包括页面结构、交互、数据口径和接口依赖。接口契约详见 `docs/api-stats-records.md`。

---

## 1. 背景与目标

### 1.1 现状问题

当前“我的”页更像一个“装备资产页”：

- 主角是球拍、球鞋两张结构几乎相同的卡片，信息密度低
- 只有“存量”数据（几把拍、几双鞋、花了多少钱），没有时间维度的积累感
- 用户在这里感受不到“我在坚持”的正反馈
- 菜单只有“意见反馈”一项，其他功能入口藏得深

### 1.2 优化目标

把“我的”页重构成「个人网球生涯总览 + 常用功能入口」：

- 一眼看到坚持：连续打球天数、累计场次/时长/花费
- 展示个人里程碑：最长单次、单月最高时长、最早记录
- 装备降级为一块概览，不抢戏
- 功能入口分组清晰

产品判断标准不变：

> 用户刚打完球、很累，也应该能在 10 秒左右完成一次记录。

“我的”页优化服务于“可回顾、长期坚持”，不改变快速记录主流程。

## 2. 需求与口径确认

| 问题 | 确认结果 |
|---|---|
| 连续天数口径 | 从今天往前连续有打球记录的天数；今天还没打不打断，从昨天开始往前计算 |
| 累计花费口径 | 与现有统计一致：打球消费 + 球拍购买费用 + 穿线费用 + 球鞋购买费用 |
| 个人记录页 | 与“我的”页记录入口一起做（常用功能中的“个人记录”入口进入完整个人记录页） |

---

## 3. “我的”页设计

### 3.1 页面结构（从上到下）

| 区块 | 内容 | 点击行为 |
|---|---|---|
| 用户头部 | 头像、昵称、连续打球天数徽章 | 头像 → 个人信息页 |
| 我的坚持 | 累计场次 / 累计时长 / 累计花费（眼睛开关）/ 冠军次数 | 无 |
| 我的装备 | 球拍、球鞋两个入口行，右上角显示装备总投入 | 球拍行 → 球拍列表；球鞋行 → 球鞋列表 |
| 常用功能 | 个人信息、个人记录、意见反馈、隐私政策 | 分别进入对应页面（个人记录 → 个人记录页） |

### 3.2 关键交互

- 头像与“个人信息”菜单项都进入 `user-profile`，避免重复入口。
- 连续打球徽章只在 `streakDays > 0` 时展示，避免展示“已连续 0 天”的负面信息。
- 累计花费默认可见，点击眼睛图标切换隐藏（`****`），与首页交互习惯一致。
- “个人记录”收敛为常用功能中的一行入口，不展示预览数据，点击进入个人记录页。
- 页面数据并行加载（用户、个人记录、球拍统计、球鞋统计），任一失败统一 toast，不静默写入本地缓存。

### 3.3 空态与异常

| 场景 | 表现 |
|---|---|
| 未登录 | 跳转登录页 |
| 服务不可用 | toast 友好提示，保留上一帧数据 |
| 无打球记录 | 连续徽章隐藏；累计数据为 0 |
| 装备为空 | 球拍/球鞋行显示 0 把/0 双 |

## 4. 个人记录页设计

### 4.1 页面结构（从上到下）

| 区块 | 内容 |
|---|---|
| 连续天数 Hero | 大数字 + “连续打球天数” + 口径说明「今天还没打不打断，从昨天往前连续计算」 |
| 个人记录卡 | 最长单次、单月最高时长、单日最高场次、历史最长连续、单月最高花费、冠军次数、亚军次数 |
| 累计数据卡 | 累计场次、累计时长、累计花费（眼睛开关） |

### 4.2 状态

- 加载中：展示加载文案
- 加载失败：展示“重新加载”按钮
- 正常：展示数据
- 空数据：数值展示 0 / “暂无”，不展示异常态

## 5. 数据口径

| 指标 | 口径 |
|---|---|
| 累计场次 `totalCount` | 全部未删除打球记录数 |
| 累计时长 `totalMinutes` | 全部未删除打球记录 `duration_minutes` 合计 |
| 累计花费 `totalCost` | 打球消费 + 球拍购买费用 + 穿线费用 + 球鞋购买费用（全量） |
| 连续天数 `currentStreakDays` | 从今天往前连续有记录的天数；今天没记录从昨天开始，昨天也没记录则为 0；同日多场按一天计 |
| 历史最长连续 `longestStreakDays` | 全部历史中连续有记录的最长天数；同日多场按一天计 |
| 最长单次 `longestSessionMinutes` | 单场 `duration_minutes` 最大值；并列时取最早达成的一场 |
| 单月最高 `bestMonth*` | 按自然月（`Asia/Shanghai`）聚合 `duration_minutes`，取合计最高月份；并列时取较早月份 |
| 单日最高场次 `maxSessionsPerDay` | 按自然日聚合记录数，取单日最高的日期；并列时取较早日期 |
| 单月最高花费 `bestMonthCost*` | 按自然月聚合打球消费 `cost`，取合计最高月份；并列时取较早月份；不含装备与穿线费用 |
| 冠军次数 `championCount` | `match_rank = 1` 的记录数 |
| 亚军次数 `runnerUpCount` | `match_rank = 2` 的记录数 |

统计规则：

- 时区统一使用 `Asia/Shanghai`
- 只统计未删除（软删除过滤）记录
- 月份统计按打球日期 `date`，不按创建时间

## 7. 边界情况

- 无任何记录：全部统计为 0 或空字符串，页面不报错。
- 今天没打、昨天打了：连续天数正常延续；昨天也没打：连续天数为 0。
- 同一天多场：连续天数按天去重，不重复计数。
- 跨月 / 跨年：单月最高按自然月聚合，跨年不影响统计。
- 存在未来日期的记录：不影响连续天数计算（只看今天及以前）。
- 删除记录：软删除后立即从所有统计中剔除。
